## Research process

Six phases, each ending in a tagged commit to the public repo. The tag is the checkpoint: a dated, immutable snapshot anyone can diff against the final paper.

1. **Pre-registration** (before any research)
   - Write and commit: this plan, the AI-use policy you'll follow, and the public/private rules.
   - Commit the transcript and Pocket summary as the origin record.
   - Checkpoint `v0-plan`.
2. **Problem and audience**
   - Use the primer and your prior article to draft 2–3 candidate problem statements and pick one.
   - Write a one-page audience memo: primary reader, what they need to decide, what they already believe.
   - Checkpoint `v1-problem`. Changes after this point get logged as deviations.
3. **Research**
   - Build the source map: Swiss foundation law, supervisory practice, a sample of major protocol foundations (structure, council composition, token holdings, dissolution terms), and existing commentary.
   - Every AI-generated summary is checked against the source before it enters the bibliography.
   - Checkpoint `v2-research`: bibliography, source notes, dataset if you build one.
4. **Argument and outline**
   - Thesis, section-level outline, the counterarguments you'll answer, and the policy recommendations in draft.
   - Checkpoint `v3-outline`.
5. **Drafting**
   - Section by section. Each section commit notes what Claude drafted vs. what you wrote or rewrote.
   - Checkpoint `v4-draft`.
6. **Review and release**
   - Outside human review (2–3 readers from the target audience) plus an independent AI review that has only the repo, not this Project's history.
   - Final AI-use disclosure footnote, deviation log, and the paper.
   - Checkpoint `v5-final`; mint a DOI via Zenodo so the snapshot is citable.

A deviation is fine; an unlogged one isn't. Format: date · what changed · why · which checkpoint it affects.
